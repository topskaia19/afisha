# Афиша — каталог городских событий

Учебное веб-приложение на **PHP 8 (MVC, PDO, PostgreSQL)**. Пользователи ищут городские события, зарегистрированные пользователи добавляют свои, администратор модерирует контент и управляет данными.

## Запуск

### Требования

- PHP 8.1 или выше.
- PostgreSQL 14 или выше.
- Расширения PHP: `pdo_pgsql`, `mbstring`.
- pgAdmin 4 или SQL Shell (для управления базой данных).

### 1. Создание базы данных

Откройте pgAdmin 4, подключитесь к серверу PostgreSQL и создайте базу данных с именем:

```sql
afisha
```

### 2. Настройка подключения

Откройте файл `config/config.php` и укажите параметры подключения к PostgreSQL:

```php
<?php
return [
    'dsn' => 'pgsql:host=localhost;port=5432;dbname=afisha',
    'user' => 'postgres',
    'pass' => 'ВАШ_ПАРОЛЬ',
    'debug_reset_link' => true,
];
```

Замените `ВАШ_ПАРОЛЬ` на пароль пользователя PostgreSQL.

### 3. Проверка расширений PHP

Выполните команду:

```bash
php -m
```

В списке должны присутствовать:

- PDO
- pdo_pgsql
- mbstring

Если `pdo_pgsql` отсутствует, включите его в `php.ini`:

```ini
extension=pdo_pgsql
```

После изменения конфигурации перезапустите PHP.

### 4. Создание таблиц и тестовых данных

Из корневой папки проекта выполните:

```bash
php database/install.php
```

Установщик создаёт необходимые таблицы, администратора, тестового пользователя, категории и примеры событий.

**Важно:** установщик предназначен для первоначальной настройки. Не запускайте его повторно без необходимости.

### 5. Запуск приложения

Выполните:

```bash
php -S localhost:8000 -t public public/index.php
```

Откройте приложение в браузере:

[http://localhost:8000](http://localhost:8000)

## 1. Функциональные возможности

- **Аутентификация:** регистрация, вход, выход, хеширование паролей (`password_hash`, bcrypt), ограничение попыток входа (5 ошибок — блокировка на минуту).
- **Восстановление пароля (доп. задание):** одноразовый токен на 1 час; в БД хранится только его SHA-256. Письмо записывается в `storage/mail.log`, в учебном режиме ссылка показывается на странице (`debug_reset_link` в конфиге).
- **Публичный раздел (без входа):** главная с тремя динамическими блоками из БД (ближайшие события, категории со счётчиками, статистика), список и карточка события.
- **Форма создания события** (7 полей: текст, textarea, select, datetime, radio, number, select возраста). Проверка на клиенте (`public/js/app.js`, атрибуты HTML5) и на сервере (`Core\Validator`), ошибки показываются под полями. События обычных пользователей попадают на модерацию.
- **Форма поиска:** ключевое слово, категория, формат, диапазон дат, максимальная цена, «только бесплатные».
- **Админ-панель (роль `admin`):**
  1. Сводка (статистика).
  2. Список всех событий, публикация событий с модерации.
  3. Редактирование и удаление событий.
  4. Список пользователей, смена роли, удаление.
  5. Создание новых администраторов.
  6. CRUD категорий (нельзя удалить категорию с событиями).

## 2. Сценарии использования

**Гость:** открывает главную → фильтрует события в `/events` → читает карточку → регистрируется.

**Пользователь:** входит → выбирает «Добавить событие» → заполняет форму, при ошибке видит сообщения у полей → событие получает статус «на модерации» → после публикации оно видно всем.

**Администратор:** входит → в разделе «События» публикует новое событие → при необходимости редактирует или удаляет его → создаёт ещё одного администратора в разделе «Пользователи».

**Забытый пароль:** `/forgot` → ссылка → новый пароль → вход.

## 3. Архитектура

```text
app/Core         Router, Database, Auth, Csrf, Validator, View
app/Models       User, Event, Category (запросы к БД)
app/Controllers  Home, Auth, Event, Admin
app/Views        шаблоны (layout.php + страницы)
public/          index.php (единая точка входа), css, js
database/        schema.sql, install.php
config/          config.php
```

Запрос → `public/index.php` → `Router` (проверка CSRF для POST) → контроллер → модель → `View`.

## 4. Структура базы данных

СУБД: **PostgreSQL**.

Основные таблицы:

```text
users(
    id, username UNIQUE, email UNIQUE,
    password_hash, role, created_at
)

categories(
    id, name UNIQUE
)

events(
    id, title, description,
    category_id → categories,
    event_date, format, city,
    price, age_limit,
    user_id → users,
    status, created_at
)

password_resets(
    id, user_id → users,
    token_hash, expires_at
)
```

Для первичных ключей используется `GENERATED BY DEFAULT AS IDENTITY`.

Связи:

- `categories 1—N events`;
- `users 1—N events`;
- `users 1—N password_resets`.

Удаление пользователя удаляет его события и токены восстановления пароля (`ON DELETE CASCADE`). Категорию с существующими событиями удалить нельзя (`ON DELETE RESTRICT`).

Для ускорения поиска используются индексы по `category_id`, `user_id`, `status`, `event_date` и `password_resets.user_id`.

## 5. Безопасность

- **SQL-инъекции:** только подготовленные запросы PDO.
- **XSS:** весь вывод через `e()` (`htmlspecialchars`).
- **CSRF:** токен в сессии, проверка для всех POST.
- **Пароли:** `password_hash` / `password_verify`; требования — от 8 символов, буква и цифра.
- **Сессии:** `HttpOnly`, `SameSite=Lax`, `session_regenerate_id` при входе, проверка роли на каждом защищённом маршруте (`Auth::requireAdmin`).
- **Восстановление:** токены одноразовые, с TTL, в БД хранится хеш; ответ не раскрывает, существует ли email.
- **База данных:** доступ осуществляется через PDO с использованием подготовленных запросов и отдельной конфигурации подключения.
